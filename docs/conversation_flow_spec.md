# 対話フロー・UX仕様書

## 1. UXの基本方針
- **回数固定の完全撤廃（相手の心の状態を察知する柔軟性）**:
  - 「1ターン目は傾聴、2ターン目は紹介」というような**機械的な回数縛りは完全に排除**します。
  - 人間同士の対話と同じように、**AIが相手の言葉や感情の機微を察して臨機応変に対応**します：
    1. **【もっと話したい・吐き出したい状態】**:
       - 相手がまだ愚痴や辛さを語っている間は、2往復でも3往復でも、何回でも徹底的に傾聴と共感を続けます。アニメの押し付けは絶対にしません。
    2. **【受け取る準備ができた・一息ついた状態】**:
       - 気持ちを吐き出し終えた、あるいは「どうしたらいいかな」「何か観て気分転換したい」「おすすめある？」など、相手の心が次に向かう準備ができた瞬間を察知して、初めて「ねえ、もしよかったら……」と作品を差し出します。
    3. **【最初から作品を求めている状態】**:
       - ユーザーが最初から「頭空っぽにして観られる作品教えて」と言っている場合は、無駄な聞き返しをせず、即座に優しく作品を紹介します。
- **心理的安全性と低エネルギー消費**:
  - 長文の壁を作らず、親しい相手とのチャットのような気軽なテンポ。
  - 入力中表示はメッセンジャーアプリのタイピングインジケータ（`● ● ●`）。
- **弱った人に優しいビジュアル（温もりと視認性）**:
  - 温かいミルクティーやキャンドルライトを思わせる**ソフトラテ・ウォームトーン**。
  - テキスト入力欄は明確なコントラストとフォーカス視認性を確保。
- **音声入力 & 音声合成（VOICEVOX / Web Speech API）**:
  - キーボードを打つ気力がない時のための「ワンタップ音声入力（マイク）」。
  - キャラクターの声を耳から優しく届ける「音声読み上げトグル（VOICEVOX / ブラウザ合成音声）」。

## 3. 入力支援 & アクセシビリティ仕様

### ① 音声入力（Web Speech API）
- マイクアイコンをタップして話すだけで、文字入力欄にリアルタイム反映。
- 弱っていて指を動かす気力がないユーザーでも発話だけで吐き出せる。

### ③ ワンクリック・作品フィードバック（既視・好み不一致）
- アニメが紹介されたカードの下に、ワンタップで意思を伝えられるボタンを常時配置：
  - `[これ、もう観たことあるよ]`
  - `[今はちょっと気分じゃないかも]`
  - `[別の作品も見てみたいな]`
- タップすると、静久が「あ、もう観てたんだね！さすが詳しいね。じゃあね、これならどうかな？」「好みに合わなくてごめんね、じゃあこっちのタイプにしよう！」と人間味たっぷりに受け止め、**即座に別の作品へスイッチ**する。

### ④ 紹介済み作品の完全重複排除（スマート履歴管理）
- セッション内で一度紹介した作品のID（`introducedAnimeIds`）を追跡。
- 同じ会話セッション中では、**同一作品が何度も重複して紹介されることを完全に防止**する。
- 作品紹介後に「ありがとう、観てみるね」などの感謝や日常の雑談が続いた場合は、無理にアニメを連投せず、温かいお見送りや他愛のない会話に付き合う。

## 4. 作品紹介のUI表現仕様
- メッセージアプリで友達から送られてくる「シェアリンク」のように、メッセージバブルの直下にコンパクトに配置。
- 契約中VODなら「あなたのネトフリにあるよ！」、未契約なら「解約忘れが心配だから無理に入らないでね」と、あくまで吹き出しまたは補足として親友目線で添える。
- カードの直下に「ワンクリック・フィードバックボタン」を付属させる。
